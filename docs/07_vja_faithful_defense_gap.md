# VJA本来の脅威モデルへの防御適用性: ギャップの特定と実証

ユーザーからの質問「VJAでも同様の防御手法は使える? VJA論文はゼロショット防御しか
提案していないため確認したい」を受けて調査した結果をまとめる。

## 1. 結論(要約)

- `docs/03`〜`docs/06` で実装した防御手法(introspective defense, guard classifier,
  DPO, curriculum DPO, 脅威語彙, immune memory)は**原理的にはVJAにも適用できる**が、
  **OCR/語彙ベースの手法はVJA本来の"visual-to-visual"(文字を伴わない矢印・丸囲み等の
  視覚指示のみの攻撃)には原理的に無力**であることが判明した。
- 実際に本リポジトリの実装で検証したところ、**旧来のOCRベース内省防御はVJA型攻撃の
  検知率0%**(600件中0件をブロック)だった。**学習済みマーク検出器を統合した新防御は
  検知率92.3%**まで改善した。
- なぜVJA論文がtraining-freeな防御しか提案していないかについては、対象が主に
  **商用クローズドモデル(重みアクセス不可)** であるためと考えられる(下記2節)。

## 2. なぜVJA論文はゼロショット防御しか提案していないのか

VJAが評価対象とするのは Nano Banana Pro / GPT-Image-1.5 等の**商用ブラックボックス
モデル**である。第三者評価者の立場では重みへのアクセスがないため、DPOのような
学習ベースの防御はそもそも適用不可能で、**モデルに依存しないtraining-free防御だけが
唯一どの黒箱サービスにも後付けできる**選択肢になる。

これに対し本リポジトリの `train_safety_dpo.py` 等は、モデル提供者側(自社でOSSモデルを
微調整する場合)を対象とした選択肢として設計している。リーダーボードに現れる
`Qwen-Image-Edit-Safe (Ours)` は恐らくこの立場(重みアクセスのある側)からの
対策例だと考えられる。

## 3. 手法別の適用可否(再掲・詳細版)

| 手法 | 重みアクセス | テキスト経由か / ピクセル直接か | VJA(非テキスト視覚指示)への適用 |
|---|---|---|---|
| `introspective_defense.py`(OCRヒューリスティック版) | 不要 | テキスト経由(OCR結果に依存) | **✗ 無力**(実測: 検知率0%) |
| `introspective_defense.py` + `mark_detector.py` | 不要(推論のみ) | ピクセル直接 | **○ 有効**(実測: 検知率92.3%) |
| `train_guard_classifier.py` | 不要(推論のみ) | ピクセル直接(画像も入力) | ○ 適用可(ただしテキストエンコーダ部分はVJAでは無意味) |
| `lexicon_optimizer.py`(3段階脅威語彙) | 不要 | テキストのみ | **✗ 無力**(文字が無ければ原理的に反応しない) |
| `train_safety_dpo.py` / `curriculum_dpo.py` | **必要** | テキスト応答のみ(現実装) | △ モデル提供者側限定、かつ現実装は画像を直接条件付けていない(4節) |
| `immune_memory_defense.py` | 不要(推論のみ) | ピクセル特徴(guard_classifier由来) | ○ 適用可、レイアウト/パターンに反応できる |

## 4. 発見した実装ギャップと対応

### 4.1 攻撃生成器がタイポグラフィ系統に偏っていた

`typography_attack.py`/`shape_obfuscation.py`/`variant_generator.py` は
「文字を画像化して隠す」系統(FigStep/MM-SafetyBench型)であり、VJA本来の
「文字を一切使わない矢印・丸囲み・矩形マーキング」による攻撃を生成していなかった。

**対応**: `src/attack/visual_instruction_attack.py` を新規実装。合成シーン画像
(有害内容を含まないプレースホルダー)にランダムな矢印/円/矩形/X印/走り書きを描画し、
テキストプロンプト側は常に無害な定型文(`BENIGN_CARRIER_PROMPTS`)に固定する。
難読化レベル(solid/dashed/dotted/faint/fragmented)も実装し、マークの
「検知回避 vs 意図伝達精度(target_bboxとの幾何学的整合性)」のトレードオフを
将来的にパレート分析できる設計にした。

### 4.2 視覚マーク検出が粗いヒューリスティックのみだった

`introspective_defense.py::extract_visual_marks()` は輪郭の頂点数(5-7角形)で
矢印らしさを判定する非常に粗いヒューリスティックで、`fragmented`/`dotted` 等の
難読化に対応できず、そもそも学習された判別力を持たない。

**対応**: `src/defense/mark_detector.py` を新規実装。`mark_variant_generator.py` が
生成したマーク付き/クリーン画像でRGB軽量CNN分類器を学習し、has_mark(2値)と
mark_type(5クラス)を推定する。

**学習上の重要な知見(誠実に記録)**:
1. 当初 `train_guard_classifier.py` のグレースケール画像読み込みを流用したところ、
   presence_accが多数派クラス精度から一切改善しなかった。**マークの識別信号は主に
   色にあり、グレースケール化で消失していた**ため、RGB読み込みに変更した。
2. RGB化後も `AdaptiveAvgPool2d` + BatchNorm無しの構成では学習が完全に停滞した
   (小規模診断実験で検証)。マークは画像全体に対してごく少数ピクセルしか占めない
   **スパースな信号**であるため、空間平均を取ると信号が消えてしまう。
   `AdaptiveMaxPool2d` + 各層への `BatchNorm2d` 追加により、
   16サンプルの過学習テストで直ちに100%まで収束することを確認した。
3. バリアントごとに背景シーンを完全にユニークに生成すると、1200サンプル程度の
   データ量では背景の見た目の違いという交絡因子に対して過学習し、検証精度が
   改善しなかった。**24枚の背景プールを使い回し**、同一背景に対して
   「マークあり/なし」のペアを作ることで交絡因子を統制し、検証presence_accを
   0.5(チャンスレベル)から0.588まで改善した。
4. 最終的な学習結果(1200サンプル、trainは presence_acc 0.81 まで到達、
   val presence_acc は最良エポックで0.588)は、**トイスケールでの機構検証としては
   十分だが、本番運用には更なるデータ量・アーキテクチャ規模の拡大が必要**である
   ことを明記する(他のトイモデル実験と同様の誠実な限界表明)。

### 4.3 検出結果が実際の判定ロジックに反映されていなかった

マーク検出器を追加しても、既存の `rule_based_reasoning`(キーワード一致)は
マーク検出結果のテキスト説明に対しても単純なキーワード検索しか行わないため、
「マークが検出されたが、それが何のカテゴリの安全ポリシーに抵触するか」を
判断する材料がそもそも無い(VJAはテキストに一切手がかりを残さないため)。

**対応**: `introspective_defense.make_mark_aware_reasoning_fn()` を新規実装。
「マーク検出器が視覚指示を検出したにもかかわらず、テキストプロンプト側に
その指示を正当化する具体的な説明が無い(短い定型文のみ)」こと自体を
VJAパターンの疑いとして扱い、人手レビューへの拒否ルーティングを行う。
これはVJA論文の「攻撃面を視覚から言語へ引き戻す」という思想を、
「言語側に説明責任を要求する」形で具体化したものである。

## 5. 定量評価: `src/eval/vja_gap_eval.py`

タイポグラフィ攻撃(324件)とVJA型視覚指示攻撃(600件)の両方に対し、
旧防御(OCRヒューリスティックのみ)と新防御(マーク検出器統合)の
検知率(ブロック率)を比較した。

| 攻撃系統 | n | 旧OCRヒューリスティック防御 | 新マーク検出器統合防御 |
|---|---|---|---|
| typography_attack(文字系) | 324 | 0.0 | 0.0 |
| **vja_visual_mark_attack(VJA型)** | 600 | **0.0** | **0.9233** |

**typography_attack行の注記**: 本リポジトリの攻撃生成器は安全設計上、
実際の有害語彙を含まないプレースホルダーテキストのみを描画するため、
キーワード一致ベースの判定はどちらの防御でも発火しない(0.0 vs 0.0 は
両防御が同等に無力という意味ではなく、テストデータ側にキーワード信号が
無いことに起因する)。この行は「テキストに実際の有害語彙が含まれる場合」の
比較には使えない点に注意。**意味のある比較は vja_visual_mark_attack 行**であり、
ここでの 0.0 → 0.9233 の改善が、OCR依存防御のVJAに対する原理的な盲点と、
マーク検出器統合によるその解消を直接示している。

再現コマンド:

```bash
python -m src.attack.mark_variant_generator --out data/sample/visual_marks
python -m src.defense.mark_detector --data data/sample/visual_marks/manifest.jsonl --save outputs/mark_detector.pt
python -m src.eval.vja_gap_eval --out outputs/vja_gap_report.json
```

   画像エンコーダ)で再学習し、type_acc(マーク種類の分類精度)を改善する
2. `unified_defense_pipeline.py` に `mark_detector_model` を渡せるようにし、
   guard_classifierと組み合わせたアンサンブル検知にする
3. `visual_instruction_attack.py` の難読化レベルと `target_bboxes` を使い、
   `compare_optimize.py` と同様の「検知回避 vs 意図伝達精度」のパレート最適化を
   マーク攻撃側でも実施する(`mark_compare_optimize.py` として今後実装可能)
4. `curriculum_dpo.py` の難易度スコアに、テキスト語彙スコアだけでなく
   マーク検出器のconfidenceも組み込み、VJA型サンプルを含むマルチモーダル
   カリキュラムを設計する
