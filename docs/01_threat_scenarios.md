# VJA 脅威シナリオ分析

防御設計(`docs/03_defense_survey.md`, `docs/04_ideal_dataset_design.md`)の入力として、
VJAが悪用されうる経路を体系的に整理する。STRIDE風に「誰が・何を・どう」の観点で分類。

## 1. 攻撃者プロファイル

| プロファイル | 動機 | 技術力 | 想定される行動 |
|---|---|---|---|
| カジュアルユーザー | 好奇心・悪ふざけ | 低 | 公開されたjailbreakプロンプト/画像テンプレートをコピーして使用 |
| コンテンツファーム | 収益化(違法/グレー画像の大量生成) | 中 | VJAパイプラインを自動化し、大量の画像編集リクエストをAPI経由で送信 |
| なりすまし/偽情報業者 | 世論操作、名誉毀損、詐欺 | 中〜高 | 実在人物の写真を編集し虚偽の文脈を付与(フェイクエビデンス生成) |
| 組織的攻撃者(APT的) | サービス評判失墜、規制リスク惹起、競合サービスの信頼毀損 | 高 | 自動化された多変量探索(遺伝的アルゴリズム等)でゼロデイjailbreakを継続発見・在庫化 |
| 研究者/レッドチーム | 脆弱性発見・開示 | 高 | responsible disclosureを前提とした体系的評価(本リポジトリが想定する主用途) |

## 2. 攻撃ベクトル(VJA特有)

1. **視覚指示の隠蔽**: 有害な編集意図を矢印・マーク・注記として画像内に描画し、
   テキストプロンプトは「画像の指示に従って編集して」等の無害な文言に留める。
2. **画像内タイポグラフィの難読化**: 有害語を通常フォントで書かず、装飾・図形化・分割・
   多言語混在などでOCRベースの安全フィルタを回避しつつ、VLMの読解力には依存する。
3. **多段階編集チェーン**: 1回の指示では安全ポリシーに抵触しないよう分割し、
   複数回の編集リクエスト(履歴)を積み重ねて最終的に有害な結果へ到達する(salami slicing)。
4. **文脈詐称/ロールプレイ併用**: 「これは映画の小道具です」等のテキスト文脈とVJAを組み合わせ、
   視覚チャネルとテキストチャネル双方の防御を同時に無力化する。
5. **良性画像への便乗**: 実在の合法画像(既存の著作物、SNS投稿画像)を土台にすることで、
   入力画像自体の異常検知(不自然な合成画像検知)を回避する。

## 3. 被害シナリオ

| # | シナリオ | 影響 |
|---|---|---|
| S1 | 実在人物の画像を性的/暴力的に改変 | 名誉毀損、精神的被害、法的責任 |
| S2 | 身分証明書・公文書の偽造編集 | 詐欺、なりすまし、金融犯罪 |
| S3 | 製品パッケージ・ロゴの改変による偽ブランド品生成補助 | 商標権侵害、消費者被害 |
| S4 | 危険物(武器・薬物関連)の合成画像生成 | 実世界の危険行為の助長、規制違反 |
| S5 | フェイクニュース用の「証拠画像」生成 | 情報操作、社会的混乱 |
| S6 | 未成年が写る画像の不適切な改変 | 児童保護に関する重大な法令違反 |
| S7 | 大規模自動化によるモデレーションコスト増大 | サービス運営コストの増加、信頼低下によるビジネス影響 |

## 4. 攻撃ライフサイクル

```
[偵察] 対象モデルの安全フィルタの挙動を把握(境界探索)
   ↓
[攻撃構築] VJA型 視覚指示の設計 + テキストプロンプトの無害化
   ↓
[最適化] フォント/色/言語/サイズ/図形化度合いを変えたバリアントをA/Bテスト
   ↓
[実行] 対象サービスへ送信、成功したパターンをテンプレート化
   ↓
[拡散] 成功パターンをコミュニティ/闇市場で共有、亜種が拡散
```

この「最適化」フェーズに直接対応するのが `src/attack/compare_optimize.py`
(攻撃者が行いうる探索を先回りして防御側が実施するための道具)である。

## 5. 防御設計へのインプリケーション

- **多段階攻撃(S1〜S3)への対応**には単発リクエストの安全性判定だけでなく、
  セッション履歴を跨いだ意図推定が必要(→ `docs/03_defense_survey.md` の「文脈追跡」節)。
- **視覚指示の隠蔽**には、テキストのみを見る既存ガードレールでは原理的に対応できないため、
  画像そのものへのOCR/VLM内省を必須コンポーネントとする(→ `introspective_defense.py`)。
- **大規模自動探索**への耐性は、単一の防御ルールでなく「攻撃者の最適化プロセスそのものを
  非効率にする」設計(ランダム化・摂動注入・多層防御)が有効(→ `docs/02_attack_enhancement_proposals.md`
  で挙げる強化攻撃に対して防御側がどこまで頑健かをこのリポジトリの評価ハーネスで検証する)。
