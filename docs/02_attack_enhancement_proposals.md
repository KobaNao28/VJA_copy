# 攻撃強化の技術的方向性(防御設計・レッドチーミング目的)

> 本ドキュメントの目的は「より強い攻撃を実装して悪用すること」ではなく、
> **防御側が想定すべき攻撃の上限(worst case)を先に把握し、防御をそれに耐えるよう設計すること**です。
> 実装は `src/attack/` にスキーマ・評価ツールとして用意し、実際の有害コンテンツ生成は行いません
> (プレースホルダーテキスト・幾何学図形のみでバリアント生成のロジックを検証します)。

## 1. 現状のVJA/タイポグラフィ攻撃が持つ弱点(攻撃者視点で見た伸びしろ)

論文・関連研究から読み取れる、現行防御が突きやすい/防御が弱い方向性:

1. **単発リクエスト最適化止まり**: 既存研究の多くは1回の編集リクエストの最適化に留まり、
   マルチターンでの意図分割(salami slicing)への最適化はまだ体系化されていない。
2. **視覚チャネルのみの最適化**: テキストチャネルと視覚チャネルを同時に最適化する
   共同最適化(joint optimization)はまだ発展途上。
3. **静的な難読化パターン**: フォント/色/レイアウトの変化は試されているが、
   「防御側のOCR/VLM judgeモデルそのものに対する適応的探索(query-based black-box optimization)」
   はまだ十分に体系化されていない。
4. **単一モデル評価**: 転移性(あるモデルで発見したjailbreakが別モデルにも効くか)の
   体系的評価が手薄。

## 2. 防御設計のために先回りすべき攻撃強化の方向性

### 2.1 マルチモーダル共同最適化(joint text-image optimization)
テキストプロンプトの無害化度合いと画像側の視覚指示の明瞭度を、
遺伝的アルゴリズム/ベイズ最適化で同時に探索し、
「安全フィルタの検知確率」を目的関数に含めて最小化する。
→ **対応する防御**: 単一チャネル判定ではなく、テキスト×画像の**共同尤度**で
  不整合(テキストは無害なのに画像指示が別の意図を示す)を検出する
  (`src/defense/introspective_defense.py` の「クロスモーダル整合性チェック」)。

### 2.2 適応的難読化のパレート最適化
「OCR/VLMでの可読性」対「自動検知器での検知確率」のトレードオフをパレートフロントとして探索し、
検知回避しつつ意図が伝わる最小限の難読化レベルを特定する。
→ 本リポジトリでは `src/attack/compare_optimize.py` として**防御側の評価ツール**として実装。
  攻撃者が同様の探索を行うことを前提に、防御側がまず自分のフィルタに対してこの探索を実行し、
  「どのレベルの難読化まで耐えられるか」を定量化する。

### 2.3 マルチターン分割(context-splitting)攻撃への拡張
1回の指示では安全ポリシーに抵触しない部分的編集を複数回に分けて依頼し、
セッション全体で有害な結果に到達する。
→ **対応する防御**: セッション単位の意図追跡・累積リスクスコアリング
  (`unified_defense_pipeline.py` に `SessionRiskTracker` として実装)。

### 2.4 転移性評価(cross-model transfer)
発見した攻撃パターンを複数モデル・複数バージョンで評価し、
「モデル固有の弱点」か「アーキテクチャ共通の弱点」かを切り分ける。
→ 防御側はこれにより、**個別モデルパッチ**ではなく**根本的な防御(データ・学習ガイドライン)**
  へ投資判断ができる(`docs/04_ideal_dataset_design.md` の設計方針に反映)。

### 2.5 敵対的摂動との併用
タイポグラフィ攻撃(意味的難読化)と、ピクセル単位の敵対的摂動(勾配ベース)を重ねがけすることで、
画像分類器ベースの前段フィルタ(NSFW検知器等)も同時に回避する複合攻撃。
→ **対応する防御**: 単一の分類器に頼らないアンサンブル検知 + adversarial training された
  guard classifier(`train_guard_classifier.py` で敵対的摂動を訓練データに含める)。

## 3. レッドチーム演習としての活用方法

1. `src/attack/variant_generator.py` でプレースホルダーテキスト・幾何学図形を用いたバリアント群を生成
2. `src/attack/compare_optimize.py` で自社の検知器に対するパレート最適化を実行し、
   「どのパラメータ帯で検知率が急落するか」を可視化
3. その閾値近傍を重点的にカバーするデータを `src/dataset/dataset_optimizer.py` で合成し、
   guard classifier / DPO学習データに追加(**攻撃の先回りをそのまま防御データにフィードバック**)
4. 定期的に(例: 月次)このループを回し、防御のドリフトを監視する

## 4. やらないこと(スコープ外)

- 実際の有害コンテンツ(暴力・性的搾取・武器製造・詐欺等)を目的とした具体的プロンプト/画像の生成
- 実サービスに対する無許可の自動化攻撃ツールの提供
- 検知回避に特化した「即戦力の攻撃キット」としての配布

本リポジトリのコードは全て、プレースホルダー入力・合成データ・防御評価目的での利用を前提に設計しています。
